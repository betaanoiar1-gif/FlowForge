# Public Feature Matrix: Google Flow Automator, GA Studio, and Google Flow

- **Research checked:** 2026-10-04
- **Scope:** Public Chrome Web Store listing/release notes, the publisher's user guide, and Google's public Flow Help Center. This is behavioral/product research only. No extension source, hidden endpoints, private APIs, DOM selectors, credentials, or access controls were inspected or reverse engineered.
- **Implementation-status note:** Public-source observations remain unchanged. Implementation cells now reflect Phases 1–3; see [ARCHITECTURE.md](./ARCHITECTURE.md), [docs/vertical-slice.md](./docs/vertical-slice.md), [docs/google-flow-provider.md](./docs/google-flow-provider.md), and [docs/application-services.md](./docs/application-services.md). Phase 2 browser/provider behavior is fake-tested only; live Flow behavior is **BLOCKED / NOT RUN**. Phase 3 adds the application-service layer and operator CLI commands (queue inspection/run, review, selection, readiness); it adds no web UI, no reordering surface, and no live Flow validation. Google Flow Automator is a third-party browser extension; its advertised features are not Google product guarantees.

## Matrix

| Feature | Publicly observable behavior | Architectural implication | FlowForge implementation / status |
| --- | --- | --- | --- |
| Project and media organization | Google Flow has projects with Images, Videos, Characters, Scenes, Uploads, and Collections. The asset browser supports search/filtering; a project can be downloaded. [Google project/assets guide](https://support.google.com/flow/answer/16935308?hl=en&co=GENIE.Platform%3DDesktop) | Keep a Flow project as an external provider workspace, not the FlowForge project graph. Map imported/generated media to stable FlowForge asset IDs and explicit project relationships. | FlowForge project/scene/version/asset records are implemented. The provider does not create or map Flow projects; outputs are imported into the existing local asset store. |
| Prompt queue | Google Flow Automator advertises queued prompts run automatically in sequence, reordering, queue tabs, and reuse of completed prompts. [Automator listing](https://chromewebstore.google.com/detail/google-flow-automator-nan/jincmbkbdocdfgljlmoididhodhenbgm) | Queue items need stable identity, order/priority, visible per-item state, and durable history independent from provider pages. | SQLite queue, leases, attempt history, idempotency, retry/recovery, and a local worker are implemented. `flowforge queue status|run|recover` expose depth, claims, and leases to an operator; no web queue UI or reordering surface exists. |
| CSV / Google Sheets import | The listing advertises CSV and Google Sheets import. The guide documents a CSV `prompt` column, preview/edit, and explicit Add to Queue before Run. [Automator guide](https://googleautomator.com/user-guide) | Import is a boundary adapter: validate/preview rows, then map to project/scene/version/job records. CSV/Sheets must not become canonical storage. | Missing. |
| Multi-line prompts and asset mentions | Automator documents `@@@NEXT@@@` for separating multi-line queue items and advertises asset matching for `@name`. The guide also instructs users to verify queue contents and selected character/reference settings before Run. [Automator listing](https://chromewebstore.google.com/detail/google-flow-automator-nan/jincmbkbdocdfgljlmoididhodhenbgm), [guide](https://googleautomator.com/user-guide) | Preserve prompt text exactly; resolve names to explicit reference IDs/versions before submission. Keep parsing/import syntax outside domain records. | Missing. Current `GenerationRequest` holds a prompt and optional string references but has no versioned reference links. |
| References, characters, and continuity | Google Flow supports visual “ingredients,” selecting project assets by `@`, and character references. Its docs describe reusable character assets with images and a voice. Automator advertises character/reference images and a multi-select ingredient picker with validation. [Flow video/reference guide](https://support.google.com/flow/answer/16353334?hl=en&co=GENIE.Platform%3DDesktop), [Flow project/assets guide](https://support.google.com/flow/answer/16935308?hl=en&co=GENIE.Platform%3DDesktop), [Automator listing](https://chromewebstore.google.com/detail/google-flow-automator-nan/jincmbkbdocdfgljlmoididhodhenbgm) | Model references as first-class, typed, versioned graph edges (project, character, world, scene, shot, prompt). Capture the exact chosen reference versions on each scene version. | The graph has characters/scenes but no versioned `Reference` model. GoogleFlowProvider rejects reference requests; continuity remains `NOT_EVALUATED`. |
| Image and video generation settings | Google's documented prompt workflow supports image/video mode, model choice, aspect/orientation, output count, video length, and optional ingredients/frames. Automator advertises image/video queue modes and named video models/settings. [Flow video guide](https://support.google.com/flow/answer/16353334?hl=en&co=GENIE.Platform%3DDesktop), [Flow image guide](https://support.google.com/flow/answer/16729550?hl=en&co=GENIE.Platform%3DDesktop) | Treat settings as a typed provider request and query provider capabilities. Avoid hard-coded assumptions about model names, limits, or availability. | Core has a provider-neutral capability contract. GoogleFlowProvider implements a fake-tested single-image/default-settings path only; video and other settings are rejected. The live UI path is unverified. |
| Start and end frames | Google's guide documents adding a start frame and an end frame for video generation. Automator's release notes also advertise last-frame capture in video mode. [Flow video guide](https://support.google.com/flow/answer/16353334?hl=en&co=GENIE.Platform%3DDesktop), [Automator listing/release notes](https://chromewebstore.google.com/detail/google-flow-automator-nan/jincmbkbdocdfgljlmoididhodhenbgm) | Model `start_frame` and `end_frame` as explicit, versioned asset references and provider capabilities. Capturing a final frame is a separate optional operation from supplying a frame. | Missing. No frame-generation capability is claimed. |
| Storyboard and scene planning | Automator advertises storyboard planning and its release notes mention storyboard UI/UX changes. Google's public help documents Scenebuilder for arranging, reordering, trimming, previewing, and downloading a sequence of clips. These are related but not the same claim: the reviewed Google docs do not establish that Automator's planning UI is a Google storyboard API. [Automator listing](https://chromewebstore.google.com/detail/google-flow-automator-nan/jincmbkbdocdfgljlmoididhodhenbgm), [Google scene builder guide](https://support.google.com/flow/answer/16935718?hl=en&co=GENIE.Platform%3DDesktop) | Keep storyboard as structured FlowForge data: narrative beat, duration, location, characters, shots, camera/action, prompts, explicit references, and continuity constraints. Do not confuse a provider clip sequence with the canonical storyboard. | Project/scene records and immutable prompt/reference snapshots exist, but there is no structured storyboard, shot model, or planner. |
| Collections | Google Flow supports collections (including nested collections); Automator advertises collection-based asset scans/generation and collection selection. [Google project/assets guide](https://support.google.com/flow/answer/16935308?hl=en&co=GENIE.Platform%3DDesktop), [Automator listing](https://chromewebstore.google.com/detail/google-flow-automator-nan/jincmbkbdocdfgljlmoididhodhenbgm) | Collections are an organization/view layer over assets, not a replacement for project, scene, reference, or version relationships. | Missing. |
| Generation detection and timeout | Automator's guide explicitly notes a queue timeout can occur while Flow is still generating and a delayed page update can make status appear stale. It advises waiting, refreshing/rescanning, and retrying only the failed item. [Automator guide](https://googleautomator.com/user-guide) | Separate submission, provider monitoring, result detection, download, and validation. Treat “unknown” as ambiguous; inspect/recover before resubmission. | Durable attempts and same-attempt recovery exist. GoogleFlowProvider uses a local request-key manifest and strict visible prompt/media correlation; ambiguous UI state raises `submissionUnknown` rather than resubmitting. Fake-tested only; live Flow correlation is BLOCKED / NOT RUN. |
| Retry, delay, and blocked states | Automator advertises configurable/randomized delays and automatic retries. Its guide describes manual Retry Unfinished, and a pause/cooldown after repeated server-side “unusual activity” blocks, stopping if the restriction recurs. [Automator listing](https://chromewebstore.google.com/detail/google-flow-automator-nan/jincmbkbdocdfgljlmoididhodhenbgm), [guide](https://googleautomator.com/user-guide) | Classify failure before choosing recovery. Respect provider/account limits; a restriction becomes `BLOCKED` and pauses for the user, not a reason to evade controls. Use bounded backoff for transient, safe-to-retry failures only. | The durable queue uses typed retryability and bounded same-attempt recovery. GoogleFlowProvider reports visible auth/block status and does not bypass or evade challenges. No randomized delay or policy-evasion retry exists. |
| Downloads | Automator advertises automatic downloads, selected/upscaled downloads, and image/page scanning. The guide describes rescanning if no images are found. Google's Flow docs describe downloading projects, collections, assets, and scenes. [Automator listing](https://chromewebstore.google.com/detail/google-flow-automator-nan/jincmbkbdocdfgljlmoididhodhenbgm), [guide](https://googleautomator.com/user-guide), [Flow scene guide](https://support.google.com/flow/answer/16935718?hl=en&co=GENIE.Platform%3DDesktop) | Make download a resumable stage with stable asset IDs, temp-file/atomic-finalize behavior, integrity hashes, and retry without regenerating. | The gateway captures visible browser download events to local staging; GoogleFlowProvider rechecks correlation before download. The existing asset store and QC handle import/integrity. Live Flow download is unverified. |
| Cancellation | The reviewed Google Flow help pages document generation, asset, and download workflows but do not define a per-generation cancellation contract or an identifier proving which generation a visible stop control affects. [Flow video guide](https://support.google.com/flow/answer/16353334?hl=en&co=GENIE.Platform%3DDesktop), [Flow assets guide](https://support.google.com/flow/answer/16935308?hl=en&co=GENIE.Platform%3DDesktop) | Distinguish local workflow cancellation from remote provider cancellation. A remote stop action requires unambiguous per-attempt ownership before it is automated. | FlowForge local cancellation is implemented (job, active attempt, and queue item become `CANCELLED`). Remote Flow cancellation is deliberately unavailable: `GoogleFlowProvider.cancelGeneration()` only finalizes pre-submission records and otherwise returns typed `FLOW_CANCEL_UNAVAILABLE`; it never clicks a generic Stop/Cancel control. |
| Asset history and versions | Google's image/video editing help describes preserving original media and viewing previous versions and prompts in an asset History stack. [Flow image guide](https://support.google.com/flow/answer/16729550?hl=en&co=GENIE.Platform%3DDesktop), [Flow scene guide](https://support.google.com/flow/answer/16935718?hl=en&co=GENIE.Platform%3DDesktop) | Keep provider history as external evidence only. FlowForge must retain its own immutable scene/prompt/reference/settings snapshot and link final outputs back to it. | FlowForge has immutable scene and asset versions with attempt provenance. The adapter does not import or rely on Flow's own history/collections. |
| Google Flow Agent | Google describes an Agent that can brainstorm/storyboard, develop mood boards/prompts, generate/edit media, make variations, organize assets, and use project media as context. Sessions are project-specific; agent-generated media is saved to the open project. [Google Flow Agent guide](https://support.google.com/flow/answer/17093911?hl=en) | A creative assistant is not the orchestration source of truth. FlowForge's planner/agents should return validated structured data and act only through explicit domain tools; credit-using actions remain user-authorized. | No AI provider, planner, agent, schema validation, or tool layer exists. |
| “GA Studio” | The Automator listing's version history contains the note “Prepare to support GA Studio” (version 2.8.5). The public material reviewed did not define GA Studio or document a supported workflow/API. [Automator listing/release notes](https://chromewebstore.google.com/detail/google-flow-automator-nan/jincmbkbdocdfgljlmoididhodhenbgm) | Treat the name as an unresolved external reference. Do not infer an integration, product relationship, API, or behavior from a changelog fragment. | **Unverified / no implementation.** Revisit only if authoritative public documentation becomes available. |
| Narration, music, captions, final publishing, analytics | The sources reviewed document voice references/custom voices for some generated video workflows and Flow asset/scene operations, but do not establish that Automator provides a production narration/music/caption/edit/publishing/analytics pipeline. [Flow video guide](https://support.google.com/flow/answer/16353334?hl=en&co=GENIE.Platform%3DDesktop) | Keep audio, captions, timeline, render, export, publish, and analytics as independent FlowForge subsystems; do not assume a generator UI supplies them. | Missing; planned after the reliable generation/review slice. |

## Architectural patterns adopted (not copied)

1. **Queue work as durable items:** one prompt/scene operation has an identity, order, status, retry history, and inspectable result.
2. **Separate planning from execution:** a structured creative plan becomes typed scene/version records; a provider only executes a request.
3. **Model references explicitly:** character/world/scene/shot/prompt references are data with version pins, not prompt text conventions alone.
4. **Observe provider state before retrying:** asynchronous generation and delayed UI updates make blind retries unsafe.
5. **Treat download/validation as distinct stages:** acquisition can fail after generation succeeds; keep recovery local to that stage.
6. **Make user review authoritative:** provider output is a candidate, not an accepted final asset.
7. **Isolate provider behavior:** Google Flow is an adapter behind capabilities and browser operations, so a mock, local model, or API provider can be substituted.
8. **Preserve the safety boundary:** use only authorized, user-controlled browser workflows and stop on security/access-control challenges.
